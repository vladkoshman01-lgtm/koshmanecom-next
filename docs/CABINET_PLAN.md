# Кабінет клієнтських дашбордів — план

`koshmanecom.com/cabinet`: клієнти бачать свої рекламні дашборди, адміни
(ми) — керують клієнтами й підключають їм звіти. Розробка повністю локальна
на емуляторах Firebase; деплой — окремою командою, коли все готово.

## Архітектура

- **Вхід** — Firebase Auth: Google і посилання на email. Паролів немає.
- **Усе через один API** — Cloud Function `cabinet`. Браузер ніколи не
  звертається до Firestore напряму (правила Firestore: заборонено все),
  тому вся перевірка доступу живе в одному місці на сервері.
- **Доступ** — на кожен запит функція перевіряє Firebase ID token, бере
  підтверджений email і дивиться, чи він адмін або член клієнта, якому
  належить дашборд. Прибрали email з клієнта — доступ зник одразу.
- **Дані** — функція сама ходить у джерело (Windsor або BizMap) і віддає
  браузеру лише готові цифри для графіків. Ключі джерел — тільки на
  сервері; відповіді кешуються в Firestore, щоб оновлення сторінки не
  палило ліміти API.
- **Модулі** — тип дашборда = як дістати дані + як показати. Новий тип пишеться
  один раз, далі підключається будь-якому клієнту з адмінки.

### Дані у Firestore (лише для функції)

| Колекція | Що там |
| --- | --- |
| `cabinetAdmins/{email}` | хто адмін |
| `cabinetClients/{id}` | назва клієнта, `members: [email]` |
| `cabinetDashboards/{id}` | `clientId`, `type`, `source`, `title`, `config` (акаунт, валюта…) |
| `cabinetSecrets/{clientId}` | BizMap-токен клієнта, зашифрований AES-256-GCM (ключ у Secret Manager) |
| `cabinetCache/{hash}` | кеш відповідей джерел, `expireAt` для TTL |
| `cabinetAudit/{auto}` | хто що змінив в адмінці і хто що відкривав |

### Джерела

- **Windsor** — один агентський ключ (`WINDSOR_API_KEY`), акаунти клієнтів
  підключені у вашому Windsor. Конектори: `pinterest`, `openai_ads`
  (ChatGPT Ads), за потреби `facebook`, `tiktok`, `google_ads`…
- **BizMap** — клієнт підключає сервіси у своєму кабінеті BizMap, ми
  зберігаємо його MCP-токен (зашифровано) і викликаємо інструменти
  `get_google_ads_*`, `get_meta_ads_summary`, `get_ga4_*`, `get_clarity_*`
  через `tools/call`. У BizMap нічого міняти не треба.

## Етапи

0. ✅ **Локальне середовище.** Емулятори Auth + Firestore + Functions,
   скрипт-сід: ви як адмін + демо-клієнт із демо-дашбордом.
   Запуск: `npm run cabinet:emulators` (Java шукається в `~/.local/jdk`), потім `npm run dev`
   і http://localhost:3000/cabinet. Посилання для входу емулятор не шле поштою — воно
   в Emulator UI (http://127.0.0.1:4000/auth). Тести доступу:
   `node functions/test/cabinet-access.test.mjs <email адміна>`.
1. ✅ **Каркас.** Окремий root layout `(cabinet)` без шапки сайту, noindex.
   Сторінка входу (Google / посилання на email), «Мої дашборди», вихід.
   Функція `cabinet`: `me`, `listDashboards`, `getDashboard`. Правила
   Firestore deny-all.
2. ✅ **Адмінка** `/cabinet/admin`. Клієнти, люди клієнта, дашборди (тип,
   джерело, акаунт), «переглянути як клієнт», керування адмінами, журнал дій.
3. ✅ (Pinterest) **Модулі й архів.** Pinterest Ads тепер напряму через Pinterest API, дані складаються у власний архів (`cabinetDashboards/{id}/periods`), щоранку `cabinetSync` дотягує останній тиждень. Стару історію Anna Sposa (1.06–10.11.2026) імпортує `scripts/cabinet-import-legacy-pinterest.mjs`. Windsor лишився джерелом для інших платформ (ChatGPT Ads — коли підключать акаунт; пробний тариф пам'ятає 30 днів). Було: Реєстр модулів, кеш. Pinterest Ads (переносимо
   поточний дашборд, дані через Windsor замість протухлого Pinterest-токена)
   і ChatGPT Ads (`openai_ads`).
4. **Джерело BizMap.** Зашифрований токен клієнта, модуль Google Ads через BizMap.
5. **Міграція і посилення.** Поточного клієнта Pinterest переносимо в
   кабінет; видаляємо `/dashboard/*`, `DashboardGate`,
   `NEXT_PUBLIC_DASHBOARD_PASSWORD` і функцію `pinterestAnalytics`.
   Ліміти запитів на користувача, заголовки безпеки, тести доступу.
6. **Деплой (лише за командою).** Увімкнути в консолі Auth (Google + email
   link), авторизовані домени, секрет шифрування, задеплоїти функцію,
   правила Firestore, хостинг; TTL на `cabinetCache`.

## Обмеження джерел

- Pinterest API: синхронна аналітика — лише 90 днів; старіше — через асинхронний `/reports`. Підключення — OAuth з адмінки (застосунок 1584168, `cabinetPinterestCallback`): ключ доступу 30 днів, ключ оновлення 60 і ротується при кожному оновленні; кабінет оновлює сам за 7 днів до кінця, токени зашифровані (`CABINET_ENCRYPTION_KEY`). У проді — задати `PINTEREST_APP_SECRET` і `CABINET_ENCRYPTION_KEY` і пройти «Підключити Pinterest» ще раз.
- Windsor (пробний тариф): 30 днів історії; `select_accounts` — просто ID акаунта.
- Імпортовані старі дані — тижнями, межі місяців не перетинають; конверсій у них немає.

- «Де придбати» в Анни: тег Pinterest шле `lead` (lead_type where_to_buy) на сторінці з `where-to-buy` у шляху (GTM-TMTMNWTZ), але рахує менше за GA4 (153 проти ≈205 за 30 днів) і майже нічого до середини жовтня. Брати з GA4 — джерело ще не вибране (напряму через сервісний акаунт або Windsor-ключ іншого акаунта).
